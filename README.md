# Задание: построение графа по предобработанному тексту

Пайплайн построения графа знаний из русскоязычных научно-технических текстов по металлургии и производству стальных труб. На вход — Markdown-файлы, на выходе — граф в формате GraphML.

## Этапы

Каждый этап читает результат предыдущего и пишет артефакты и `metrics.json` в `output/<stage>/`.

| # | Этап | Что делает |
|---|------|-----------|
| 1 | `clearing` | Чистка Markdown: изображения, ссылки, разметка; HTML-таблицы → Markdown; защита формул и таблиц |
| 2 | `normalization` | Нормализация единиц, дат, чисел, формул (SymPy), таблиц; лемматизация (pymorphy3); замена аббревиатур |
| 3 | `chunking` | Разбиение на чанки по 800 токенов (`cl100k_base`) с перекрытием 15 % |
| 4 | `tokenization` | Гибридная токенизация, формулы как отдельные токены |
| 5 | `vectorization` | Dense-векторы (`intfloat/multilingual-e5-small`) + sparse TF-IDF для чанков и таблиц |
| 6 | `graph_building` | Извлечение сущностей и связей через Ollama (`qwen3.5:9b-q4_K_M`) по онтологии, сборка графа (NetworkX) |
| 7 | `graph_building_default` | Отдельный граф из очищенных `.md` в `output/clearing/`, до нормализации и лемматизации, с разбиением по символам |

Результаты: `output/graph_building/knowledge_graph.graphml` и `output/graph_building_default/knowledge_graph.graphml`. У каждого графа свои метрики. Оба этапа используют модель из `configs/llm.json`; второй повторно обращается к Ollama, поэтому полный запуск займёт больше времени, чем построение одного графа.

## Структура

```
main.py            # точка входа, конфигурация этапов
constants.py       # ключи для метрик и результатов этапов
pipeline/          # реализации этапов (base, clearing, normalization, chunking, ...)
configs/
  config.json      # параметры построения графа
  ontology.json    # типы сущностей и связей
  llm.json         # модель, API Ollama, контекст и параметры генерации
  extract.txt      # промпт для извлечения графа
input/             # входные .md-файлы (создать вручную)
models/            # модель эмбеддингов E5 (скачивается автоматически)
output/            # результаты (создаётся автоматически)
```

## Установка

Требуется Python ≥ 3.10; для Windows рекомендуется Python 3.13. Для извлечения графа нужна актуальная Ollama. На Windows/Linux `uv sync` устанавливает PyTorch из официального индекса CUDA 13.0; для RTX 5070 нужен совместимый драйвер NVIDIA (Windows ≥ 580.88).

```powershell
uv sync --python 3.13
ollama pull qwen3.5:9b-q4_K_M
```

Команды выполняются из корня репозитория. PyTorch CUDA нужен для операций Python на GPU; Qwen запускается отдельным процессом Ollama и использует GPU независимо от PyTorch. E5 по умолчанию остаётся на CPU (`dense_device="cpu"` в `main.py`), чтобы оставить видеопамять Qwen. Для ускорения E5 можно поставить `dense_device="cuda"`.

Проверка PyTorch после синхронизации:

```powershell
uv run python -c "import torch; print(torch.__version__); print('CUDA:', torch.version.cuda); print('Available:', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'GPU unavailable')"
```

Ожидаются версия с `+cu130`, CUDA `13.0`, `Available: True` и RTX 5070. `None` для CUDA означает CPU-сборку. CUDA Toolkit отдельно для готовых сборок PyTorch/Ollama устанавливать не нужно.

## Запуск

1. Запустите приложение Ollama. Если оно не запущено как приложение, выполните `ollama serve` в отдельном терминале и оставьте его открытым. API должен быть доступен на `http://localhost:11434`.
2. Положите документы с расширением `.md` в `input/` (в репозитории уже есть примеры).
3. Запустите пайплайн:

```powershell
uv run python main.py
```

Если предыдущий прогон ещё работает, остановите его через `Ctrl+C` перед повторным запуском. Изображения (включая base64) удаляются на этапе `clearing`; оба прохода построения графа используют текст без них. Исходные файлы в `input/` менять вручную не требуется. Удалять `output/` перед перезапуском тоже не нужно.

При первом запуске нужен интернет для `multilingual-e5-small` и кодировки `tiktoken`. Qwen скачивается заранее командой `ollama pull` и хранится в Ollama; копировать её в `models/` не нужно. Если включена обработка стоп-слов NLTK и данных нет, выполните `uv run python -m nltk.downloader stopwords`.

Каждый этап показывает прогресс по файлам. На этапе графа есть дополнительная строка `[graph] <документ>`: число обработанных чанков, процент, прошедшее время, скорость и оценка оставшегося времени. Шкала обновляется после завершения запроса к модели; на первом чанке она может стоять на месте во время загрузки модели. Загрузка E5 при первом запуске также может занять время.

Во время построения графа можно проверить размещение Qwen:

```powershell
ollama ps
```

`100% GPU` в `PROCESSOR` означает полную загрузку модели в видеопамять. Частичная загрузка на CPU может замедлить обработку. Закройте другие приложения, занимающие GPU, если памяти не хватает.

Графы записываются в `output/graph_building/knowledge_graph.graphml` и `output/graph_building_default/knowledge_graph.graphml`, метрики — в `output/<stage>/metrics.json`. Повторный запуск заново обрабатывает документы и перезаписывает соответствующие результаты; возобновления с последнего чанка нет. При ошибке API Ollama этап завершается с ошибкой, вместо того чтобы молча сохранить пустой граф.

## Настройка

- Параметры этапов (чистка, чанки, векторизация, словарь аббревиатур и терминов) задаются прямо в `main.py`.
- Онтология графа — `configs/ontology.json`, промпт — `configs/extract.txt`, ограничения на узлы и рёбра — `configs/config.json`.
- Ollama — `configs/llm.json`: `llm_ollama_model`, `llm_ollama_url`, `llm_timeout_seconds` (600 секунд на запрос), `llm_keep_alive` (`30m`), `llm_context_tokens` (8192, общий контекст), `llm_max_new_tokens` (1024, максимум ответа). Thinking отключён. Ollama сама выбирает GPU; `llm_device` больше не используется.
- `llm_max_context_chars` (2000) ограничивает текст каждого чанка; это прежнее ограничение пайплайна. Слишком длинные фрагменты обрезаются. При предупреждении о достижении лимита ответа проверьте результат и при необходимости увеличьте `llm_max_new_tokens` вместе с бюджетом контекста.

## Замечания

- Для текущих 169 чанков время определяется в основном генерацией Qwen. Замерьте 5–10 чанков после загрузки модели и умножьте среднее время на общее число чанков: 10 секунд/чанк → около 28 минут, 20 → 56 минут, 40 → 113 минут только на построение графа. Это расчётные примеры, не измерение RTX 5070.
- Параметр `vector_store="qdrant"` в `VectorizationConfig` пока только метка в метаданных: клиент Qdrant не подключается, векторы сохраняются в JSON.
- Все входные файлы должны иметь расширение `.md`.
